# 国内更新发布

《塘里》使用自己的 Ed25519 公钥验证更新清单，签名覆盖版本、完整 EXE 哈希、分片哈希和各镜像地址。官方 GitHub 与镜像读取同一份签名清单；只有签名及完整文件校验都通过才会安装。镜像只是传输服务，可能限速、失效或在某些网络无法访问。

所有仓库、镜像、公钥及旧版兼容分支配置集中在 `update-channel.json`；客户端检查地址和发布时的分片地址都由同一份配置生成。更新检查并发请求，各地址最多等待 5 秒；下载没有固定总时长，单次连接 20 秒没有数据时会切换地址。旧版 v1.1.1、v1.1.2 使用的 `updates/latest.json` 继续同步。

## 密钥

应用内只包含公钥。独立签名私钥保存在发布者用户目录 `.tangli-release-signing/update-ed25519.pem`，GitHub Actions 使用仓库加密密钥 `TANGLI_UPDATE_SIGNING_KEY`。请保留安全备份，不要将私钥提交到仓库、分享给他人或复用其他项目的密钥。Windows 的目录可能继承宽松权限，生成或恢复密钥后应检查目录和文件 ACL。

私钥丢失后，已安装的程序无法验证新密钥签署的更新；需要先让用户手动安装包含新公钥的程序。能够修改发布工作流或读取仓库 Actions 密钥的人也必须视为受信任的发布者。

## 自动发布

1. 修改 `package.json` / `package-lock.json` 的版本，编写 `docs/releases/v<版本>.md`，运行 `npm run check:updates` 和 `npm test`，提交并推送代码。
2. 给该提交打对应的正式版本标签，例如 `v1.2.0`，推送标签。GitHub Actions 将自动构建、签名和发布；不要在同一标签上并行手工发版。
3. 发布工作流会检查标签、项目版本、EXE 内部版本及更新代码，生成签名清单、48 MiB 分片与 `SHA256SUMS.txt`。上传到草稿后逐一比较远端附件的大小和 SHA-256，验证通过后发布，并更新旧版读取的兼容清单。
4. 如工作流中断，可通过 GitHub Actions 手动运行 `Publish Tangli` 并填写原标签。已有附件会先核对；若内容不一致或已有更新的正式版，流程会停止，不会覆盖附件或倒退版本。
5. 发布后在无代理环境验证清单及完整下载；第三方缓存可能使最新清单延迟出现。若无法访问 GitHub 的用户仍在使用 v1.1.0 或更早版本，需提供新版镜像下载链接让他们手动升级一次。

本地准备与验证（不会上传或发布）：

```powershell
node tools/prepare-domestic-update.cjs build 'dist/Tangli-v1.2.0-Windows-x64.exe' '1.2.0' 'dist/domestic-v1.2.0' "$env:USERPROFILE/.tangli-release-signing/update-ed25519.pem" 'docs/releases/v1.2.0.md'
node tools/verify-update-release.cjs 'dist/Tangli-v1.2.0-Windows-x64.exe' 'dist/domestic-v1.2.0' '1.2.0' 'dist/release-v1.2.0/win-unpacked/resources/app.asar'
```
